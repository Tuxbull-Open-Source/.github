<h1 align="center">TuxBull Open Source</h1>

<p align="center">
  Practical open source for Linux, automation, infrastructure, and agent-assisted engineering.
</p>

---

TuxBull is an open source community built around a simple idea: useful engineering should be understandable, reproducible, and open to improvement.

We create tools, documentation, and working examples for people who operate real systems. Some projects start with a recurring task. Others begin with an experiment that proved useful enough to share. In both cases, we aim to leave behind something that another person can inspect, run, and maintain.

## What we work on

Our interests include:

- Linux and self-hosted systems
- Automation with Ansible, Python, and shell
- Containers, Kubernetes, and repeatable deployments
- AI inference and practical agent workflows
- Troubleshooting, observability, and operations
- Runbooks and documentation written for real users

The subjects may vary, but the standard stays the same: clear purpose, honest status, and enough evidence for others to judge the work for themselves.

## How we work

### Build things people can use

A repository should solve a problem, explain its limits, or teach something worth carrying forward. We prefer small and maintainable projects over clever systems that nobody can safely change later.

### Verify before we claim

If we say something works, we try to show how it was tested. Depending on the project, that may include automated tests, reproducible commands, compatibility notes, or documented validation results.

### Write for the next person

Good documentation is part of the project. A new user should be able to understand what a repository does, whether it fits their situation, and how to get started without reverse-engineering the maintainer's thought process.

### Keep public work safe to share

Our repositories contain reusable code, sanitized examples, and public documentation. Secrets, customer data, private infrastructure details, and sensitive operational information do not belong here.

### Keep humans accountable

We use AI agents where they help: research, implementation, testing, review, and documentation. Agent-assisted work is still reviewed by human maintainers. The people publishing a project remain responsible for its direction, claims, and risks.

## Where TuxBull comes from

TuxBull brings together two existing bodies of work:

- [Tuxmint Open Source](https://github.com/Tuxmint-Open-Source), focused on practical, security-conscious infrastructure and reusable operational tooling
- [Bitbull Ideas](https://github.com/Bitbull-Ideas), focused on Linux automation, experiments, AI infrastructure, and human-agent collaboration

The new name combines **Tux**, the familiar Linux penguin, with **Bull**, representing the Bitbull roots and a willingness to tackle difficult problems directly.

TuxBull is the shared home for what comes next. Existing projects will move when it makes sense; their history and licenses will remain intact.

## Explore the work

Repositories are currently being brought together and organized. Browse the [TuxBull repositories](https://github.com/orgs/Tuxbull-Open-Source/repositories) to see what is already available.

Project maturity varies. Each repository should state whether it is an idea, an experiment, work in progress, released software, or a validated setup.

## Join the community

You do not need to be an expert to take part. Useful contributions include:

- reporting a reproducible problem
- improving an unclear explanation
- testing a project in a different environment
- proposing a smaller or safer approach
- contributing code, examples, or documentation

Start with the README and contribution notes in the repository that interests you. If something is missing or confusing, opening an issue is already a useful contribution.

## Our working motto

> Build clearly.  
> Test honestly.  
> Share what others can use.
